Highlight Maker - 自動ハイライト動画を作る（スマホ用：iPhone / Android）

■ 何ができる
  スマホの写真・動画を 10 個くらい選ぶと、音楽の拍に合わせて切り替わる
  1 分〜2 分のハイライト動画を自動で作り、写真アプリに保存できます。

■ 個人データについて
  ・写真・動画・曲は、スマホのメモリの中だけで処理します。インターネットには一切送りません。
    ページに「通信禁止」の設定（Content-Security-Policy: connect-src 'none' など）を入れてあり、
    仮にプログラムが送ろうとしてもブラウザが止めます。
  ・Cookie や端末の保存領域（localStorage など）も使いません。
    ページを閉じる・再読み込みする・「今すぐ全部消す」を押すと、素材も曲も完成動画も消えます。
  ・残るのは、自分で「写真に保存／ダウンロード」した完成動画だけです。
  ・写真の日付は「動画に日付を入れる」にチェックした時だけ動画に入ります（初期設定はオフ）。
  ・アプリのページを置いている場所（GitHub Pages）に届くのは、ページを開いたという記録だけです。

■ スマホで開く
  ・公開 URL：https://bntnf461-design.github.io/myproject2/
    （初回だけ GitHub の Settings → Pages → Source を「GitHub Actions」にして公開します。
      .github/workflows/highlight-pages.yml が highlight フォルダを公開します。
      既定ブランチ以外から公開する時は Settings → Environments → github-pages でそのブランチを許可）
  ・iPhone は Safari（iOS 15 以降、おすすめ iOS 17 以降）、Android は Chrome で開きます。
  ・共有ボタン →「ホーム画面に追加」で、アプリのように使えます。
  ・パソコンでは START_HIGHLIGHT.bat（または highlight\HighlightMaker.html を Edge / Chrome で開く）。

■ Android アプリ版（android フォルダ）
  ・中身は Web 版と同じ画面（highlight/HighlightMaker.html をアプリに入れています）。
  ・インターネットの権限を持たないアプリです。写真・動画・曲を外へ送ることができません。
    端末のバックアップにも含めず、アプリを閉じるとメモリの中身も消します。
  ・写真・動画は Android 13 以降なら「写真の選択ツール」で選べます（アプリに写真全体の許可は不要）。
  ・完成動画は「📲 ギャラリーに保存」で 動画フォルダ／HighlightMaker に保存され、「↗ 共有」で LINE などに送れます。
  ・APK の作り方：GitHub Actions の「Highlight Maker (Android APK)」が自動で作ります。
    実行結果ページの Artifacts → HighlightMaker-apk（zip）をダウンロードし、中の HighlightMaker.apk を
    スマホで開いてインストール（「提供元不明のアプリ」の許可が必要）。
  ・署名は開発用の鍵（android/app/highlight-dev.keystore）です。Google Play には出せません。
  ・対応：Android 8.0 以降。

                ディスコ／ピクニック／おもちゃ箱／カーニバル／ウクレレ／運動会／ハンドクラップ

  しっとり・感動（2）：シネマ／バラード
  和風（1）：和風
  どれも端末の中でその場で作曲します。🎲 を押すたびにメロディが変わります。

■ 画面（v2）
  ・「① 素材 → ② 音楽 → ③ 雰囲気 → ④ タイトル → ⑤ 仕上げ」の順に 1 画面ずつ進みます。
    上の番号をタップすると、どの手順にもすぐ戻れます。済んだ手順には ✓ が付きます。
  ・再生・停止・保存のボタンは、いつも画面の下にあります。
  ・デザインは 3 種類：右上の丸をタップで切り替え（ナイト／ポップ／シネマ）。
  ・オープニングのタイトルは 12 種類＋おまかせ。サブタイトル（日付・場所など）も入れられます。
    映画のオープニング／ポンポン弾む／文字の中に映像／ドーン！／カウントダウン／キラキラ／
    ネオンサイン／タイプライター／デジタル解読／スライド合体／手書き風／飛び込みズーム
    「▶ タイトルだけ見る」で最初の数秒だけ確認できます。

■ 使い方
  1. ①「ここをタップして写真・動画を選ぶ」→ 写真アプリから 10 個くらい選ぶ
  2. ② BGM を選ぶ
     ・内蔵BGM 27 曲（上の一覧）はその場で作曲。
       イントロ→Aメロ→盛り上げ→サビ→間奏…と展開し、サビではカットが速くなります。
     ・「自分の曲を使う」は「ファイル」アプリなどに保存した mp3 / m4a / wav。
       （Apple Music・Spotify などの配信曲は使えません）
  3. ③ パターンを選ぶ（17 種類）。「🎲 別パターンを作る」で毎回ちがう仕上がりに。
  4. ④ 画面の形（縦長 9:16 が初期設定）・長さ（1 分／1 分 30 秒／2 分／曲に合わせる）・タイトル
  5. ▶ 再生で確認 →「⬇ 保存」。再生と同じ時間がかかります（2 分の動画なら約 2 分）。
     書き出し中は画面を開いたまま、他のアプリに切り替えないでください（画面は自動で消えません）。
  6. 「📲 写真に保存／共有」→「ビデオを保存」で写真アプリに入ります。
     （Android は「ダウンロード」でも OK。保存形式は mp4、古いブラウザでは webm）

■ 注意
  ・iPhone はマナーモードでも音が出るようにしています（iOS 16.4 以降）。
  ・長い 4K 動画をたくさん選ぶと、古いスマホではメモリ不足になることがあります。
    その時は数を減らすか、画質を 720p にしてください。
  ・動作確認：node tests/test_highlight.js（Node.js と Playwright が必要）

NG MONITOR v82 - 決まった時刻を過ぎたら鳴らす・NGが○秒続いたら鳴らす

「20:00を過ぎても機械の電源が入っていたら鳴らす」「ドアが5分以上開いたままなら
鳴らす」といった使い方ができるようにしました。設定は ③ の「鳴らす条件」です
（エリアごと）。

■ 決まった時間帯だけ監視する
  ・「決まった時間帯だけ監視する」にチェックを入れ、時間帯と曜日を選びます。
  ・20:00～06:00 のように終わりが始まりより前なら、翌朝まで続きます。
    同じ時刻（例 0:00～0:00）にすると一日中（曜日だけで決める）になります。
  ・夜をまたぐ時間帯の曜日は「始まった日」で見ます
    （月～金にすると、金曜 20:00～土曜 6:00 は監視、土曜の夜は監視しません）。
  ・時間帯の外では鳴りません（タイルは「時間外」）。NGのまま時間帯が終わると
    自動で解除し、ログに「NG解除（時間帯の終わり）」を残します。
  ・時間帯が始まった時にすでにNGの状態なら、その時点で鳴ります
    （例：20:00 ちょうどに電源が入ったままなら、20:00 に鳴る）。

  ＜例＞ 20:00 を過ぎて機械の電源が入っていたら鳴らす
    1. 電源ランプ・操作画面など、電源が入っていると分かる場所を囲む
    2. 電源が入っている今のうちに →「異常の時だけ出る画面が映っている」
       （＝電源が入っている状態を覚えさせる）
       電源が切れている時に設定するなら →「正常な画面が映っている」
       （＝電源が切れた状態を正常として覚えさせる）
    3. ③で「決まった時間帯だけ監視する」→ 20:00 ～ 06:00
    4. 必要なら「NGの間、10 分ごとに鳴らし直す」

■ NGの状態が○秒続いたら鳴らす（待ち時間）
  ・ドアを開けてすぐ閉めた・人が通っただけ、では鳴らさず、開けっぱなしの時だけ
    鳴らす、といった使い方です。0 秒ならすぐ鳴ります（今まで通り）。
  ・待っている間、タイルの札に「あと1分20秒」のように表示します。
  ・途中で元に戻ったら、待ち時間は最初からやり直しです。

■ NGの間、○分ごとに鳴らし直す
  ・今までは NG になった時に1回鳴るだけでした。電源の切り忘れのように誰かが
    気づくまで知らせたい時に使います。「✔ 確認しました」を押すと止まります。

■ 試験
  tests\test_logic.ps1 に、時間帯（日またぎ・曜日）、保存・読み込み、
  待ち時間（途中で閉めたらやり直し）の試験を追加しました。

NG MONITOR v81 - 精度と使いやすさのブラッシュアップ（見た目を案A「コマンドセンター」に）

■ 精度
  1. 朝・夕方など、ゆっくりした明るさの変化に自動で合わせる（「比べる」）
     監視中、正常と判断できている間だけ、見本を少しずつ今の明るさに合わせます
     （約100秒かけて追いつく速さ）。急な変化や、NG・NGに近い部分は覚えません。
     ・試験：明るさが 1.0 → 0.55 までゆっくり暗くなる場面
         以前 … 23/91 コマで誤NG　→　v81 … 誤NG 0
       暗くなった後の「小さな部品なし」「ランプ点灯」も検知。
       部品なしが300回続いても、覚え込まずにNGのまま。
     ・記録した見本そのもの（保存される方）は書き換えません。
       「詳しい設定」のチェックを外すと、記録した見本に戻ります。
  2. 除外する場所（「比べる」「異常の画面」）
     ロボットのアーム・人の通り道・時計など、正常でも動く場所を、プレビュー
     映像の上でドラッグして囲むと判定から外せます（20か所まで）。
     ・「除外する場所を指定」→ 左の映像の上をドラッグ（斜線の部分が除外）
     ・「除外を全部消す」で元に戻せます
     ・範囲を選び直すと除外も消えます
     ・試験：アームが動く場面で誤NG 1.00% → 0.00%。除外のすぐ外のランプ点灯は検知。
  3. 長めに記録する（約30秒・150コマ）
     「★ かんたん設定」の下のチェックを入れてから「① 正常な状態を記録」。
     アームや人の動きなど「正常でも変わる」様子をまとめて覚えます。
     （除外したくない・動く範囲が広い時に）
  4. 暗くて色の少ない場面で、赤ランプなどの点灯を見逃すことがあった不具合を修正
     白黒（赤外線）カメラ対策で色の比較を止める条件が広すぎて、暗く色の少ない
     場面では色の違いを全く見ていませんでした。今は「片方だけカラーで、もう片方が
     白黒」の時だけ色の比較を止めます。（昼カラー／夜白黒の試験もそのまま合格）

■ 使いやすさ（画面）
  ・紺色を基調にした見やすい配色にしました
  ・エリアの一覧をタイル表示にしました
      今の映像・状態の札（OK／NG／確認中／待機／未設定など）・メーター
      （黄色い線＝しきい値）・判定のしかたを1枚ずつ表示します。
      クリックで選択、ダブルクリックで画面上の位置を表示、
      最後の「＋ エリアを追加」タイルからも追加できます。
  ・NGの表示に「どこで・何が・いつから」を出すようにしました
      例）⚠ NG　2号機 部品トレイ
          正常と違う（違い 0.32%）　14:31:52 から（1分20秒）
  ・「✔ 確認しました」ボタン
      NGの時だけ表示されます。押すと音が止まり、表示が「確認済み」に変わります
      （ログにも「確認」として残ります）。元に戻ると自動で解除され、別の場所で
      新しくNGになった時は、また赤く表示されます。
  ・今日の集計を表示（NGの回数・NGだった時間・最後のNGの時刻）
      再起動しても、ログのCSVから今日のぶんを読み直します。

■ 設定ファイル
  v80 までの設定ファイルはそのまま使えます（除外なし・明るさの自動追従あり）。

■ 試験
  tests\test_vision.ps1 に v81 の試験（明るさの変化・動くアーム・長めに記録）を追加しました。
  tests\test_logic.ps1 に 除外・自動追従の保存、今日の集計 の試験を追加しました。

NG MONITOR v80 - 「異常の時だけ出る画面が出たらNG」を追加

警報画面・エラー表示など、異常の時だけ表示される画面が出たら
ブザーを鳴らせるようにしました。

■ どんな時に使うか
  「正常な映像と比べる」は、正常な時の画面がほとんど変わらない場合に向いて
  います。設備の操作画面のように、正常でも数値・グラフ・時刻が変わり続ける
  画面では、その変化でNGになってしまいます（試験でも誤ってNGになりました）。
  このような画面では、「異常の時だけ出る画面」のほうを覚えさせ、その画面が
  出た時だけ鳴らす方が確実です。

■ 設定のしかた
  1. 「＋ エリアを追加」で、警報画面・エラー表示が出る場所を囲む

  ・警報画面が何種類かある場合は、①を何回か押して全部覚えさせられます（6枚まで）

    ・このアプリが ng_images フォルダに保存したNG画像

  ※ スクリーンショットは、今と同じ画面の配置（ウィンドウの位置・大きさ）で

NG MONITOR v76 - 検査精度の改善・画面の使いやすさ改善・不具合修正

■ 検査精度が悪かった原因（調べて分かったこと）

    ・判定方法（通常／色味重視）

NG MONITOR v61 - バグ修正版（複数エリア機能の検証）

前回追加した「複数エリア監視」機能を中心に検証し、実際に見つかった

   → エリア選択中は一時的に監視を止め、選び終わったら自動で

4. 【軽微な無駄】エリア一覧の表示を更新するたびに、文字の

NG MONITOR v54 - 拡大時の余白修正版

【今回の修正】
ウィンドウを大きく（特に最大化）したとき、下部に大きな白い
空白ができてしまう不具合を修正しました。

原因：
  一番下の状態表示パネル（「①→②→③の順に…」と出る部分）が、
  ウィンドウの下端に合わせて一緒に伸びる設定になっていました。
  この待機中の背景色がほぼ白に近い色のため、大きく引き伸ばすと
  「白い空白」のように見えていました。

対応：
  状態表示パネルの高さを固定し、ウィンドウを大きくしても
  伸びないようにしました。余った分は背景色（濃紺）のままになり、
  不自然な白い空白は出なくなります。

NG MONITOR v53 - 暗所対応・ウィンドウリサイズ対応版

【追加①】暗い場所での検出精度を改善
  「①検出したい色の部分を四角く囲んで選ぶ」の中に
  「暗い場所でも検出しやすくする（色味を重視）」というチェック
  ボックスを追加しました。

  通常の判定は、色のRGB値（明るさを含む）の近さで比較しています。
  暗い場所ではランプ等が暗く写り、RGB値が想定と大きくズレるため、
  検知しづらくなることがあります。
  このチェックを入れると、明るさの影響を受けにくい「色味（Hue）」を
  中心に比較する方式に切り替わり、暗い場所でも同じ色として
  認識しやすくなります。
  ・明るい場所・色の差がはっきりしている場合　→ チェックなし（通常）
  ・暗い場所、証明が不安定な場所　→ チェックあり
  設定はほかの項目と同様に保存・読み込みされます。

  ※あわせて、可能であればカメラ側の露出・ゲインを上げる、
    検出したい部分に小さな照明を追加する、といった対策も
    組み合わせるとより安定します。

【追加②】ウィンドウのサイズ変更に対応
  今まで最小化はできてもウィンドウの大きさは固定でした。
  枠をドラッグして自由に大きく（横方向にも）できるようにしました。
  ・最大化ボタンも使えるようになりました
  ・小さくしすぎて文字が見えなくなることがないよう、
    最小サイズを設定してあります（それより小さくはなりません）

NG MONITOR v52 - 実測配置版（文字切れ・重なりの根本対策）

【今回の修正】
v51で文字サイズと余白を見直しましたが、実機の写真を確認したところ、
まだ「NG検知の割合」の文字が「NG検知の割」で切れる、「秒ごとに
チェック」と説明文が重なって読めなくなる、という問題が残っていました。

原因：
  日本語の文字幅は、Windowsのバージョンやフォントの状態によって
  微妙に変わることがあります。これまでは「だいたいこのくらいの
  幅だろう」と数値を決め打ちしていたため、実機での実際の幅と
  ズレて文字が切れたり重なったりしていました。

根本的な対応：
  数値の決め打ちをやめ、「ラベルを表示した直後に、実際に描画された
  幅をプログラム自身に測らせて、その右側に次の部品を配置する」
  方式に変更しました。これにより、実際のフォントの幅がどうであっても、
  文字が切れたり重なったりすることがなくなります。
  （画面の高さも、内容に合わせて自動で計算するようにしました）

操作方法・保存機能・検出ロジックなど、見た目以外は変更していません。

NG MONITOR v51 - レイアウト全面修正版（文字切れ対策）

【今回の修正】
「Windows実機でUIが途切れる（文字が切れる）」という報告を受け、
画面レイアウトを全面的に見直しました。

原因：
  前バージョンは画面を小さくまとめるため、文字のサイズを6.5〜7pt
  まで縮小し、表示欄のサイズもぎりぎりに詰めていました。実際の
  Windows環境ではフォントの描画幅が想定と少し異なることがあり、
  この「ぎりぎり設計」だと文字がはみ出して見えなくなる
  （＝途切れる）ことがあります。

対応：
  ・文字サイズを7.5pt以上に統一（極端に小さいフォントをやめました）
  ・説明文やラベルなど、内容によって長さが変わる項目は
    「自動でサイズを合わせる」設定に変更し、多少レイアウトが
    ずれても文字が消えないようにしました
  ・各項目の間隔にも余裕を持たせ、画面全体の高さを
    560px → 630px に調整
  ・操作方法・保存機能・検出ロジックなど、見た目以外は
    変更していません
