# Nライン切面孔明け作業日報（デジタル版）

日報「品質記録：№5-(7)-10」を HTML 化した入力フォームです。
`index.html` を Edge か Chrome で開くだけで使えます（インストール・ネット接続は不要）。
決まった仕様は `仕様メモ.md` にまとめています。

## 画面
- 上の段：保存・素板QR・テンキー→カウンター・設定・データ（左）、終業・完成・印刷（右）。その下の細い帯に、カウンターの状態・保存・共有フォルダの状態をまとめて出す
- **作業画面**（ふだんはこちら）：カウンターの状態と不良の合計、今日の良品の合計、素板（前残・読んだパレット・当残）、明細の要約、「あと入れるもの」、大きな「終業」「完成して印刷」ボタン。欄に入れた値は帳票の同じ欄に入る。「あと入れるもの」や明細の行を押すと、帳票のその欄へ移る
- **帳票（印刷イメージ）**：A3 の帳票そのもの。確認や細かい直しに使う。印刷はいつも帳票で出る
- 開いたときは前回の画面で開く（はじめは作業画面）。アドレスの末尾を `#form` にすると帳票、`#work` にすると作業画面で開く

## 毎日の起動
- `起動_カウンターと日報.bat` をダブルクリックすると、Edge で不良数カウンター（左）と日報（右）を左右に並べて開く
  - この bat と `index.html`・`defect-counter.html` を同じフォルダに置く
  - 画面の大きさに合わせて、bat の中の `SCREEN_W`（横）・`SCREEN_H`（縦）・`COUNTER_W`（カウンターの幅）を変える
  - Edge がすでに開いているときは、位置や大きさが指定どおりにならないことがある（そのときは手で並べる）
  - 2つを別のウィンドウにしておくと、裏のタブになってテンキーがカウンターへ届かなくなる心配がない

## はじめに
1. 「設定・データ」→「Excel から読み込み」で `templates/マスタ登録_雛形.xlsx` を読み込み、画面の下の「保存して閉じる」（保存しないで閉じようとすると確かめます）
2. 作業者の名前も設定画面で登録（日報で手打ちした名前は自動で増える）

## 主な機能
- **型式を選ぶと自動入力**：パレット形態・ローカルコード・使用面取りホイール・良品枚数（1PL の残り）
- **切面ロットNo. の自動採番**：`YYMMDD-連番NK`。パレット（1PL）が満タンになるごとに連番 +1
- **前日からの引継ぎ**：前日の切面ロットNo.・良品端数・型式・素板ロット・素板の当残（→前残）
- **素板QR**：どの欄にいても読み取れる（ツールバーの欄でも可）。素板ロットが変わると次の行へ。使用素板（品種・インチ・mm・枚数・PL数）を記録し、当残を計算。型式とローカルコードが違うと警告
- **不良数カウンター取込**（「設定・データ」の「カウンターから取込」。同じパソコンのカウンターは自動）：共有フォルダの JSON（またはバックアップ）から、その日の不良数をいま入力している行へ、作業の開始・終了と段取りを稼働状況へ。何度取り込んでも二重に足さない
- **1台のパソコンでカウンターと日報を使う**：カウンターと日報を同じパソコンの Edge / Chrome で開いておくと、日報の画面で押したテンキー（数字・＋−＊／．・テンキーの Enter）はカウンターへ送られる。日報の数字は、キーボードの上の段の数字で入力する。ツールバーの「テンキー→カウンター」で切り替え（外すと赤く「テンキーは日報に入ります」と出る）。カウンターの画面が開いていないときは、テンキーの数字は日報にも入れずに知らせる。カウンターの状態（作業中・停止中・休憩中・不良数）は日報の上に表示し、今日の日報ではカウンターで数えた不良をその場で今の行へ取り込む
- **日報からカウンターを操作**：日報の型式は、カウンターの製造種類に自動で追加（カウンターが作業していないとき）。作業中のカウンターと違う型式を「今日の良品の合計」の②以降（またはいまの行）で選ぶと、カウンターの作業を終了し、前の型式の作業枚数を作業数として入れ、新しい型式で作業を開始する。カウンターが作業していないときは、上の帯の「カウンターで作業開始」で始める。日報とカウンターの型式が違うときは帯に赤で知らせる。登録されていない型式（打ち間違い）では、カウンターを切り替えず製造種類にも足さない（型式欄が赤くなる）
- **カウンターの休憩**は、稼働状況に E（除外）として入り、稼働時間から除く
- **自動計算**：作業枚数（良品＋不良）、良品歩留、不良の合計、合計行、投入時間合計、使用素板の当残
- 自動で入った値は青い文字。手で書き換えるとそのまま残り、空にすると自動に戻る
- **印刷**：A3 横 1 枚。シールを貼る欄は 55mm × 55mm（6 か所）。行の高さは印刷のときに決めてあるので、パソコンのフォント（Windows の游ゴシックなど）が違っても 1 枚に収まる。Edge の印刷画面では、用紙サイズ A3・横・倍率「既定」・余白「既定」で印刷する
- 下の段の確認者の欄は、「マーク仕様確認」（年月度マーク・確認者）と「ダブルチェック」（年月度マーク・確認者）を同じ高さで上下に分けている。下の段の枠は、左・中・右の下端をそろえている
- 入力は作業日ごとにブラウザへ自動保存（開いただけでは保存しない）。JSON 書出し/読込み、明細の CSV 書出し
- 起動するといつも今日の日報を開く。作業日は ◀ ▶「今日」ボタンでも変えられる
- 同じ日報を2つのタブで開くと、あとから開いたタブは表示専用になる（「このタブで入力する」で切り替え）
- 1PL を超えた良品枚数・マイナスの当残は赤く表示
- 上の行と同じ型式・切面ロットNo.・素板ロットNo.・パレット形態・ローカルコードは「〃」で表示（画面・印刷とも。値はそのまま残り、欄を選ぶと見えて直せる）
- 画面では文字と行を大きくし、明細の左4列（PL・型式・切面ロット・素板ロット）を固定（横にスクロールしても見える）。いま入力している行は黄色。印刷は A3 の配置のまま
- JSON 書出し/読込み・CSV 書出し・表示中の日報のクリアは「設定・データ」の中
- 明細表では Enter・↓ で下のセルへ移動（Shift+Enter・↑ で上へ）。明細の外では Enter で次の欄へ。作業日で Enter を押すと、いま入力中の行へ。F2 でいつでも、いま入力中の行へ
- 数字の欄は、ホイールや ↑↓ で値が変わらない
- **取り消し**：素板QRの読み取り・行を消す／入れる・読んだ素板の取消は、上のメッセージの「取り消す（元に戻す）」で元に戻せる
- **行を消す・入れる**：明細の欄を選ぶと上に「この行を消す」「この行の上に1行入れる」が出る
- **読んだ素板の一覧**：使用素板の下に、QR で読んだ素板パレットが出る。間違えて読んだものは「取消」で外せる
- メッセージは上に固定（下の方を入力していても見える）。QR が読めたら短い音、確認が要るときは低い音2回
- **印刷の前の確認**：作業者・投入時間（板乗せ・検査・ストックのどれか1つに入っていればよい）・開始と終了・マーク確認・検視台・各行のパレット№ が空なら一覧を出し、押すとその欄へ移る。あわせて、不良があるのにレ点がない列・1PL を超えた行・登録されていない型式・マイナスの当残も知らせる。画面では、入れ忘れやすい欄が空のあいだ黄色の枠で示す
- 画面では、右の3列（パレット№・形態・ローカルコード）も固定。下の段は入力欄を先に、シール欄をあとに小さく出す（印刷の配置は変えない）

## カウンターの記録を日報で直す
- 稼働状況の一覧で、カウンターから取り込んだ停止・段取り・休憩の時刻を直せる。「分」の欄で直すと終了の時刻が変わる（例：押し忘れで 60 分 → 実際は 30 分）
- 直したものは「カウンターから修正（元 10:00〜11:00・60分）」と元の値を残し、取り込み直しても上書きしない。「カウンターの値に戻す」で戻せる。削除したものも取り込み直しで戻らない
- 開始(S)・終了を手で直したときも、その値が残る（空にするとカウンターの値に戻る）。不良の数は明細の欄を直せばよい
- 最後のロット（いちばん下の行）で、良品＋不良が作業枚数（手で入れた使用数）を超えたときは、超えた分の不良を、カウンターで先に数えたものから前の素板パレットの最後の行（素板ロットNo. が違う、いちばん近い上の行）へ自動で移して知らせる（「取り消す」で戻せる。戻したあとは、数を変えるまで移さない）。手で入れた不良は移さない。どの行でも良品＋不良が作業枚数を超えていれば、印刷の前の確認で知らせる
- 日報で直してもカウンター側の記録は変わらない（カウンターの記録はカウンターの「記録の修正」で直す）

## 良品の合計から明細を作る（パレットの切り替わりを報告しない運用）
- 「今日の良品の合計」に、型式ごとに作った順で良品の合計を入れると、明細の行を自動で作る（最初の型式は前日から）
  - 製品パレットが 1PL で満タンになったところ（前日の端数は、前日と同じ型式のときだけ最初の型式に続ける。型式が変わると次の連番）と、素板パレットが切り替わったところ（前残・QRで読んだ枚数で数える）で行を分ける
  - 不良はすべて最後の行に入れる。パレット№ は行の順に残す
- 素板のQRを読むと作り直す。ただし、型式・素板ロット・良品枚数を手で直した行があるときは自動では作り直さず、「明細を作り直す」で作り直す
- 完成の前の確認で、良品の合計と明細の良品枚数の合計が違えば知らせる

- 前日と違う型式から始める日は、前日の端数を引き継がず新しい連番にする。同じ型式を1日に2回作るときも、型式が変わるたびに新しい連番
- 当残を数えて入れると、最後の素板で実際に使った枚数（素板の枚数 − 当残）がわかる。最後の素板の行の良品＋不良がそれを超えたら、超えた分の不良を、カウンターで先に数えたものから前の素板の最後の行へ移す
- 「今日の良品の合計」の②以降に型式を入れると、作業中の不良数カウンターもその型式に切り替える。良品の合計は、あとから入れても、カウンターのその作業の「作業数」（良品の合計＋その作業でカウンターが数えた不良）に書き込む

## 共有フォルダへの保存
- 「設定・データ」→「保存先のフォルダを選ぶ」で共有フォルダを選ぶと、入力するたびに「Nライン日報_日付.json」を書き直す（1日1ファイル。日本語の名前で書けないときは nline-nippo_日付.json）
- ブラウザを開き直したときなどに許可が切れたら、ツールバー右の「共有フォルダに保存できていません」を押すと再開する

## 端数の素板の紙
- 印刷するときに、当残があるパレットごとに、素板ロットNo. のバーコード（Code128）・QRコード・品種・サイズ・残りの枚数・ローカルコードを A4 縦に1枚ずつ印刷する（日報の A3 と同じ印刷で出る）。当残がないときは印刷しない
- QRコードの中身は、元の素板ラベルのQRと同じ形で、枚数（AD）だけを残りの枚数にし、端数の紙の印（ZH1）を足したもの。QRもバーコードも、この日報の中で作る（ネットにつながっていなくてよい）
- 次の日に端数の紙のQRを読むと、新しいパレットとしては足さず、前日から続く素板として確かめる（前残と枚数が違えば知らせる）
- 様式は仮。正式な雛形を受け取ったら差し替える。使わないときは「設定・データ」でオフにできる

## 毎日の手間を減らす工夫
- 新しい日は、作業者・確認者・ダブルチェックの確認者・検視台の高さ・コアドリル径を前日の値から入れる（青い字。年月度マークは同じ月のときだけ）
- 投入時間は、稼働の開始(S)〜終了から休憩など除外（E）の時間を引いた時間（0.1 時間単位）を、作業者が入っている欄に自動で入れる（直せる）
- 板乗せは、ふだんロボットなので、作業者も時間も入っていなければ斜線で印刷する（入れると斜線が消える）
- **終業ボタン**：今日の良品の合計・素板の当残・作業者と投入時間・年月度マークと確認者・検視台・稼働の開始と終了を1つの画面で入れ、「確認して完成・印刷へ」で完成の確認に進む

## 素板QRの読み忘れ・読む順番の間違い
- 素板ロットごとに「QRで読んだ枚数（前日から続く素板は前残）」と「明細の作業枚数の合計（良品枚数を入れた行だけ）」を比べ、超えた時点で「QRの読み忘れではありませんか？ ○行目あたりから次の素板の可能性」と音と赤い帯で知らせる
- 前の素板の枚数を超えてから新しい素板のQRを読んだときは、「どの行から使いましたか？」と聞き、選んだ行から新しい素板ロットにする（QRで作った行は消す）
- 行の帯の「素板ロットを選ぶ」で、読んだ素板の一覧から素板ロットNo. を選び直せる（読む順番を間違えたときも手打ちなしで入れ替えられる）。下に続く同じロットの行もまとめて変えられる。どの操作も「取り消す」で戻せる

## 完成（提出）と訂正
- 「完成（提出）」を押すと、入れ忘れ・値のおかしいところ・計算の食い違いを一覧にして確かめる。そのまま完成するか、完成して印刷する
  - 計算の食い違い：素板の枚数を超えた作業枚数、当残（手で入れた残数と計算）、前残（前日の当残と）、前日の良品端数・切面ロットNo.（前日の日報と）、不良数（不良数カウンターと日報）
- 完成した日報は入力できなくなる（印刷の左上に完成の日時が出る）。「訂正する」で直せ、「訂正を完成する」で、直した項目を元の値と一緒に「訂正の記録」に残す（印刷には訂正の回数と最終日時）。「訂正をやめる」で完成したときの内容に戻る
- 印刷ボタンでも、同じ確認を出す

## テスト
```bash
NODE_PATH=$(npm root -g) node tests/run.js        # 全部（Playwright と Chromium が必要）
NODE_PATH=$(npm root -g) node tests/run.js h3     # 名前に h3 を含むテストだけ
COUNTER_HTML=…/defect-counter.html NODE_PATH=$(npm root -g) node tests/run.js   # 本物のカウンターとの連携も確かめる
```
見本 10/21 の再現、印刷（A3 横 1 枚・シール欄 55mm）、評価で見つかった不具合（H1〜H4・M1〜M3・M5）、使いやすさの査定で直したところ（U1〜U8）を確かめる。雛形の xlsx は、英数字名の一時ファイルにコピーして読み込む（Playwright が日本語名のファイルを渡せないことがあるため）。

## 注意
- データはこのパソコンのブラウザの中に保存します。共有フォルダを選んでおけば、そこにも1日1ファイルで保存します（選んでいないときは、定期的に「JSON書出し」で保存してください）
- バーコードリーダーで読むときは、日本語入力をオフにしてください
