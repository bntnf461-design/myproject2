# 6軸ロボット 3Dシミュレーター 引き継ぎ（v2.0）

## 1. 目的
安川電機 MotoSim のような社内用 6軸ロボットシミュレーター。安川／ファナックの両システムを切り替えて使う。社内専用（商品化しない）が、現場のティーチング練習・サイクル検討に使える完成度を目標にする。

## 3. 重要な規約（壊しやすい点）
- **座標系**：ロボット座標（Z上向き）⇔ Three.js：`(X, Y, Z) = (x, -z, y)`。変換は `RS.robotToThree / threeToRobot / matrixFromPose / poseFromMatrix`。
- **関節の向き**：S+ 反時計回り、L+ 前傾、U+ 上腕が上がる、B+ 手首が下向き。R/T は腕軸まわり。
- **関節角の保存形式**：各システムの角度（ファナックは J3 水平基準）。内部の相対角との変換は `RS.toKin / RS.fromKin`。
- **ツール座標**：Z がフランジから外向き。手首フレームのローカル軸との対応は `RS.TOOL_BASIS`（Xt=+y, Yt=+z, Zt=+x）。tools.js の形状・TCP・吸盤位置はすべてツール座標で書く。
- **姿勢角**：`R = Rz(rz)·Ry(ry)·Rx(rx)`（安川 Rx/Ry/Rz、ファナック W/P/R）。ツール下向き・X 合わせ = (180, 0, 0)。
- **逆運動学**：肘上解のみ。S は ±360 で参照に近い値。手首は2解から参照に近く可動範囲内のもの。B≒0 は特異点（R を保持）。
- **直線補間**：`RS.planLinear` が 4mm／1.5° ごとに IK を解いて関節列を作り、再生時はその列を smoothstep で辿る。1サンプルで 20° 超の関節変化は特異点として拒否。
- **動作時間**：関節＝各軸 `|Δ| / (最高速度 × VJ% × オーバーライド)` の最大 × 1.5（smoothstep のピーク速度補正）。直線＝距離／速度、姿勢変化／180°/s、各軸速度の最大 × 1.5。
- **ハンド出力**：OUT ON で吸着（または閉）。その時点と、ON のまま動いている間も毎フレーム吸着判定する。WAITIN は 3 秒でアラーム。
- **干渉**：tools.js の `probes`、手首・肘・フランジ、保持ワーク底面の角を、床・台（AABB）・ワークと比べる。許容 2〜3mm。

## 4. 動作確認（自動テスト済み）
`tests/smoke.js`（Playwright）で以下を確認済み。
1. 起動・JS エラーなし、初期ハンドがガラス 4吸盤
2. サンプル作成 → 再生でガラスを供給台から排出台へ（安川・ファナック両方）
3. 繰り返し＋自動供給で 3 サイクル連続
4. 2爪グリッパ・単吸盤で箱を搬送
5. 関節ジョグ長押しで動き、離すと止まる
6. 直交ジョグ Z+ で Z だけ変化（X/Y/姿勢は不変）
7. 位置指定の直線移動で目標到達、届かない位置はメッセージ
8. 床への突っ込みで干渉アラーム → リセット
9. 安川ペンダント：サーボOFFでジョグ不可、ON でジョグ、挿入、再生モードでスタート、ホールド
10. ファナックペンダント：SHIFT なしでジョグ不可、TP+DEADMAN+SHIFT でジョグ
11. LS／JBI／JSON の書き出し→読み込み往復
12. スマホ幅（390px）で横スクロールなし

`tests/kin.test.js` で両機種 約6000 姿勢の FK→IK→FK 往復一致を確認。

## 5. 既知の制限
- 寸法・可動範囲は汎用値（実機ではない）。
- 干渉チェックは代表点のみ。アームと台・アーム同士の面干渉は見ていない。
- 肘下解・S 軸の後方解は使わない。
- 位置決め（PL／CNT）は FINE 相当のみ。ユーザ座標・ツール番号は 0／1 固定。
- JBI の位置は直交形式（RECTAN）のみ。パルス形式は機種ごとの係数が必要なため未対応。
