# 6軸ロボット 3Dシミュレーター 引き継ぎ（v3.0）

## 1. 目的
社内の教育とプログラム検証に使う 6軸ロボットシミュレーター（MotoSim／ROBOGUIDE の簡易版のイメージ）。安川／ファナックを切り替えて使い、実機のプログラムを読み込んで動かせて、作ったプログラムを実機に持っていけることを目標にしている。

## 2. 版ごとの変更
- **v2**：単一 HTML から分割構成にした。6軸の逆運動学、直線補間、ガラス用 4吸盤ハンド、ハンド定義ファイル、干渉チェック、アラームを追加した。
- **v3**
  - プログラムを「実機と同じ命令文＋位置データ」で持つように変えた（`program.js`）。v2 の保存データは起動時に変換する。
  - インタプリタ（`interp.js`）を追加：ラベル、ジャンプ、CALL/RET、変数・レジスタ、PR、Offset/Tool_Offset、SFTON、IMOV、I/O 待ち、PULSE、PAUSE、OVERRIDE。
  - 実機の JBI（PULSE / RECTAN / USER）と LS（関節／直交＋CONFIG、継続行）の読み込みと書き出し。複数ファイルの読み込み。
  - 複数プログラムの管理、テキスト編集、文法チェック、I/O パネル、変数パネル、実行ログ。
  - AI タブ：日本語の指示から INFORM／TP を作成・修正する（API 直接、またはキーなしでのコピー＆貼り付け）。
  - 設定タブ：機種の寸法（上腕オフセット a3 を追加）、可動範囲、パルス係数、ユーザ座標（UF1〜5）。
  - ロボットの 3D 形状を作り直した（`model.js`）：鋳物風の腕、モーター、姿勢に追従するケーブル、映り込み。
  - 自動供給・自動払い出しをプログラムの作りに依存しない方式にした（台が空なら補充、ロボットが離れたら払い出し）。

- **v3.1**：ペンダントを実機風に作り直した（安川：モード切替キー・イネーブルスイッチ・試運転、ファナック：TP スイッチ・F キー・STEP・SHIFT+FWD の押している間だけ動く連続実行・操作盤 CYCLE START）。3D 画面の上に重ねて表示できる。マウス操作のため SHIFT・イネーブル・デッドマンはトグル式。

- **v3.2（DX200）**：安川側を DX200 に合わせた。挿入/削除/修正はエンターで確定、前進は移動命令のみ（インターロック＋前進で全命令）、試運転はインターロック必須、微動・高速、命令一覧、ダイレクトオープン、メインメニュー（システム情報）、座標表記「直交」、JBI の `///POSTYPE ROBOT`、JBI の Shift_JIS 書き出し（`RS.encodeSJIS`）。

- **v3.3（査定と是正）**：別セッション 2 本（コードの正しさ／実機との整合・安全）で査定し、指摘 32 件を是正。
  - 関節角の向き：`robots.js` の `sign[]`（初期値 B/J5 反転、待機姿勢 -90°）と `jointConfirmed`。未確認の間は関節位置を直交で書き出す。保存済みデータは起動時に J5 を反転して移行（`conv:2`）。
  - CONFIG：Flip＝J5>0、回転数＝J4/J5/J6（半開区間 `ceil((q-180)/360)`）。D/B 形態は IK で `err:'config'`。
  - パーサ：移動命令の未知オプションは UNKNOWN、PL は 0〜8、FANUC IF の形式検査、式の厳密検査（`RS.evalExpr`）、TIMEOUT,LBL の飛び先検査、名前の規則（`RS.cleanName(s, sys)`）、改行の混入防止。
  - インタプリタ：B/I/D の範囲・整数化、0 除算、未設定 PR（クリア `PR[n]=PR[n]-PR[n]` は可）、TIMEOUT の時間は `$WAITTMOUT` 相当の別設定、飛び先なしはアラーム。
  - 実行：未対応命令は既定で停止。1 行実行・押している間の運転はインタプリタを引き継ぐ（`stepKeep`）。ペンダントは押している間だけ動き、離す・SHIFT/イネーブル/デッドマン解除で止まる。教示モードの速度制限（`motLim`）、ファナック T1/T2/AUTO。
  - 干渉：板ガラスへのめり込み判定を上面基準に修正、下腕・上腕の点と安全柵を追加。
  - 書き出し前の警告を行番号つきで詳しく。サンプルに排出台の空き確認、ハンド OFF、UFRAME/UTOOL を追加。
  - 堅牢性：localStorage の型検査、複製名の無限ループ、削除直後の前進の例外、ケーブル再生成の間引き、払い出しワークの dispose、可動範囲の空欄。

## 3. 重要な規約（壊しやすい点）
- **座標**：ロボット座標（Z上）⇔ Three.js `(X,Y,Z)=(x,-z,y)`。行列で扱う場合、ロボット座標の行列 `raw` と Three の行列は `M = C4·raw` の関係（`app.js` の `C4`）。
- **関節の階層**：`model.js` の Group 階層と `kinematics.js` の `fkKin` は同じ変換列にする（`tests/smoke.js` の「3D と FK が一致」で確認できる）。
- **ファナック J3**：水平基準（内部の相対角 U = J3 + J2）。`RS.toKin / RS.fromKin`。
- **位置データ**：`{k:'j', q}` または `{k:'c', p:{X..rz}, cfg, uf, ut, q?}`。`q` は IK で解を選ぶときの参考値。安川の教示は関節、ファナックの教示は直交（実機と同じ）。
- **関節角の向き**：内部の計算は `fkKin` の向き（B+＝手首が下）。画面・保存・書き出しの角度は `sign[]` を掛けたメーカーの向き。変換は `RS.toKin / RS.fromKin` だけで行う。
- **CONFIG**：Flip＝J5>0、回転数＝J4/J5/J6。実機の $TURN_AXIS で要確認。
- **インタプリタ**：移動以外の命令は 1 フレーム内で続けて実行する（3000 命令で無限ループと判断してアラーム）。移動は `{t:'move'}` を返して app 側が実行し、終わったら `done()` を呼ぶ。1行実行は `tick(dt, true)`。
- **未対応の命令**：既定では止める（設定で飛ばすに変えられる）。移動命令の未知オプションも未対応扱い。
- **入力待ち**：シミュレーター独自のアラーム（既定 10 秒、0 で実機と同じく無限に待つ）。安川の `T=` は時間で先へ、ファナックの `TIMEOUT,LBL[]` は別設定の時間（既定 30 秒）で飛ぶ。

## 4. 動作確認（自動テスト）
- `tests/kin.test.js`：両機種で約 6000 姿勢の FK→IK→FK の往復と、CONFIG 指定。
- `tests/prog.test.js`：命令の解析、LS/JBI の読み込み（継続行・PULSE・RECTAN）、書き出しの往復、インタプリタ（ループ、CALL/RET、タイマ、待ちのタイムアウト、無限ループ）、`programs/` の見本ファイル。
- `tests/smoke.js`（37 項目）：サンプル 3 回の繰り返し（安川・ファナック）、実機形式 LS の読み込みと実行（Offset・レジスタ・ジャンプ）、テキスト編集の誤り検出、グリッパ・単吸盤、AI 回答の取り込みと実行、ジョグ、直線移動、干渉アラーム、両ペンダント、書き出しの往復、機種寸法の変更、スマホ幅。

## 5. 既知の制限
- 初期の寸法は汎用値。実機の機種が決まったら「設定」で合わせる（`robots.js` の初期値も更新するとよい）。
- 肘下解・S 軸後方解なし。円弧（C / MOVC）は直線で近似。CNT / PL は FINE として動かす。付加軸・ステーション軸・ベース軸は読み込まない。
- JBI の `RCONF` は 0 固定で書き出す。LS の CONFIG は独自の決まりで付ける。実機では形態を確認すること。
- 干渉チェックは代表点のみ。
- ファナックの .LS を実機で読むには ASCII ロードのオプションか ROBOGUIDE 等での変換が必要。
- JBI は既定で Shift_JIS で書き出す（設定で UTF-8 も可）。読み込みは UTF-8 / Shift_JIS の両方に対応。
- 実機で未確認の点（要確認）：関節角の向き、RCONF 各欄の意味、CONFIG の回転数の軸、Offset の姿勢成分、DX200 の前進が JUMP/CALL をどう扱うか。
